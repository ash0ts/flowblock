# Worker verification

On 2026-10-29, the actual SAM 2.1 Small checkpoint was loaded and run on this Apple Silicon machine in MPS mode with CPU fallback for unsupported PyTorch operations. No CUDA host was used.

The five-second, 320×180 fixture generated by `tests/generate_synthetic.py` contains a simple drawn bottle moving horizontally. Its video visibly says `SYNTHETIC PIPELINE FIXTURE`. The source has 75 frames at 15 fps. The seed is at 2.4667 seconds and a correction at 4 seconds. Inference ran forward and backward around the seed, using the real predictor. All 75 frames produced masks accepted by the current uncertainty rules. This is a count of accepted masks on one simple synthetic fixture, not a segmentation-accuracy estimate or evidence of performance on creator footage.

The successful local artifacts are in ignored `artifacts/synthetic/result-mps/`, with the original synthetic input and its explicit target boxes in `artifacts/synthetic/`. `analysis.json` records the checkpoint hash, source revision, device, timestamp map, all mask measurements, and coverage. No framing finding was produced against the fixture's matching targets. Those targets come from the fixture generator, not a manually annotated field sample.

At the original `framing-v1` smoke run, the worker suite passed 49 checks: pure measurement and input validation, real FFmpeg decoding including FFV1 and rotation metadata, normalized mask measurements, private object-key validation, and actual PostgreSQL lease/publication checks. The database checks use a fresh disposable schema and remove it after each test. They include expired-lease replacement, retry limits, cancellation, take deletion/expiry/owner changes, deletion during the first and last artifact upload, and cleanup after a partial file write. These lifecycle tests use arbitrary text artifacts; they do not simulate model predictions.

The subsequent review introduces `framing-v1.1`. It requires three distinct source timestamps for a framing finding, keeps the actual selected mask when source timestamps repeat, uses the last sampled source timestamp for duration evidence, and marks non-finite logits uncertain. A decoded-duration check rejects a shorter video stream hidden by longer container metadata. The original MPS receipt remains `framing-v1`. A separate [review receipt](../docs/verification-review.json) records a fresh local MPS inference with `framing-v1.1`: 75 usable measurements from the same synthetic clip, a duration finding against an eight-second plan, and acceptance of a manually supplied five-second revision. No training was rerun for the review. The expanded suite passed 61 checks. Added regressions use synthetic measurements, generated JPEGs, real FFmpeg, and PostgreSQL. They also exercise expired failure updates, readback during an in-progress commit, and connection failures before commit, after a real commit, and during commit readback.

Creator footage with manually reviewed masks, difficult occlusion, handheld motion blur, reflections, transparent products, and shot cuts remains unvalidated. A useful next evaluation should retain the original clip, a short human-annotated frame sample, mask-versus-annotation overlap, coverage, and adjudicated findings. The current thresholds should be revised from those observations rather than treated as a calibrated quality score.
